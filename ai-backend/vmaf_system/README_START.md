# VMAF 启动说明

## 快速开始

双击运行根目录下的 **`start.bat`**，脚本会自动：

1. 检查 Python / Node 环境（缺依赖会自动安装）
2. 检查 8000 / 5173 端口是否被占用
3. 启动后端与前端（各弹出一个命令行窗口）
4. 等待服务就绪后自动打开浏览器

启动完成后访问：

| 地址 | 用途 |
|---|---|
| http://127.0.0.1:5173 | **可视化画布**（主界面） |
| http://127.0.0.1:8000/docs | 接口文档（Swagger UI，可直接调接口） |

## 停止服务

任选其一：

- 关闭弹出的两个命令行窗口（"VMAF Backend" 与 "VMAF Frontend"）
- 双击运行 **`stop.bat`**（自动结束占用 8000 / 5173 端口的进程）

## 常见问题

**提示端口被占用**

上次运行可能没关干净。先运行 `stop.bat`，再运行 `start.bat`。

**页面显示"未连接"**

后端还没起来或已崩溃。看后端那个命令行窗口有没有报错；
也可以手动访问 http://127.0.0.1:8000/health 确认。

**首次启动很慢**

第一次运行需要安装前端依赖（npm install），可能要几分钟。
之后再启动会很快。

**修改代码后需要重启吗**

- 后端插件（`plugins/tools/*.py`）：**不需要重启**。文件指纹变化后扫描器会走
  受控重载（`loader.reload_module`，含 `.pyc` 失效处理），下次 `/health`、`/schema`
  或 `/run` 请求会自动重新执行改过的文件；刷新页面即可看到节点变化。
  受保护的契约/核心模块（`plugins/base.py`、`scanner.py`、`core/*`、`utils/*`、`main.py`）
  不允许热重载，改这些仍需重启后端。
- 前端：Vite 支持热更新，改完自动刷新，无需重启。

## 关于脚本为什么是英文

`.bat` 文件里写中文会遇到两个 Windows 的老问题：

1. **编码错乱**：cmd 默认用 GBK 代码页解析批处理，UTF-8 保存的中文会被截断，
   甚至把半截文字当成命令去执行，报出 `'xxx' is not recognized` 这类费解的错误。
2. **特殊字符干扰**：中文全角括号、`echo [...]` 后的方括号等，在批处理里也可能
   干扰解析。

因此 `start.bat` / `stop.bat` 刻意只用 ASCII 英文，所有中文说明放在本文件里。
这样做同时也避免了"换台电脑就乱码"的问题。

如果确实需要中文提示，正确做法是：脚本存成 **GBK/ANSI 编码**（而非 UTF-8），
并且**不要**在脚本里使用 `chcp 65001`——那条命令会让 cmd 改用 UTF-8 解析文件，
反而导致乱码。
